# ADR-006 - Tarifação extensível por câmara

>**Estado:** Aceite 
>**Data:** 2026-10-28 
>**Componentes afetados:** Tarifação, Registo de Viagens

## Contexto

Já hoje existem dois tarifários com regras diferentes: o do assinante e o do ocasional (R3). Duas câmaras vizinhas mostraram interesse em usar a plataforma com tarifários próprios (C7). A extensibilidade é uma das top 3. No [ficheiro 02](02-componentes.md) (secção 8), a Tarifação tem instabilidade 0, porque o Registo de Viagens depende dela, mas é o componente que mais vai mudar. Na secção 9 foram identificadas conascência de posição e o risco de conascência de algoritmo entre os dois componentes.

## Decisão

- A Tarifação expõe **uma única interface estável**, "calcular o valor de uma viagem", que recebe um objeto com campos nomeados: hora de início, hora de fim, tipo de cliente e câmara.
- **Cada tarifário é uma implementação separada** dentro do componente: assinante de Lisboa, ocasional de Lisboa e, no futuro, um por cada câmara. A implementação é escolhida pela câmara e pelo tipo de cliente.
- **Só a Tarifação calcula blocos de tempo.** O Registo de Viagens envia apenas as horas de início e de fim.

## Consequências

- Uma câmara nova significa uma implementação nova, sem alterar nenhum outro componente (cenário de extensibilidade do [ficheiro 01](docs/01-caracteristicas.md)).
- A interface estável protege o Registo de Viagens de mudanças nos tarifários.
- Cada tarifário traz mais código e mais testes, o que pesa numa equipa de 6 pessoas (trade-off com o C8).
- Se um tarifário futuro precisar de dados que a interface não recebe, a interface tem de mudar, e isso afeta o Registo de Viagens.

## Alternativas rejeitadas

- **Uma só fórmula com parâmetros configuráveis (minutos grátis, tamanho do bloco, preço)** - só funciona se todos os tarifários tiverem a mesma forma, o que não está garantido para as outras câmaras.
- **Condições no código por câmara** - cada câmara nova obrigaria a alterar o código existente.
- **Tarifários carregados como extensões em tempo de execução** - complexidade a mais para uma equipa de 6 pessoas com orçamento fixo (C8).
