# ADR-007 - Isolar o percurso de cada viagem num componente próprio

>**Estado:** Aceite 
>**Data:** 2026-10-28 
>**Componentes afetados:** Percursos, Telemetria, Registo de Viagens, Relatórios Municipais

## Contexto

O percurso de cada viagem é dado pessoal (C5b). A telemetria das bicicletas elétricas contém a sua posição em andamento (C1b), ou seja, é a origem do percurso. O relatório mensal (R7) e os futuros dados abertos (C6) usam dados das viagens, mas não podem expor dados pessoais. As faturas guardam-se durante 10 anos (C5a), mas o percurso não deve ter esse prazo.

## Decisão

- O componente **Percursos** é o único que guarda e acede às posições de cada viagem.
- Para fora, expõe apenas a **distância de cada viagem**, que os Relatórios Municipais usam para calcular o CO2 evitado.
- O percurso tem um **prazo de retenção próprio**, separado do das faturas.

## Consequências

- O dado pessoal fica num só lugar, com acesso e retenção próprios.
- A regra é verificável por uma fitness function - só Telemetria e Relatórios Municipais podem importar `percursos`.
- Os Relatórios Municipais conhecem menos sobre Percursos (Lei de Deméter,  [ficheiro 02](02-componentes.md), secção 11).
- Há mais um componente a manter.
- A Consulta de Histórico não mostra o trajeto da viagem.

## Alternativas rejeitadas

- **Guardar o percurso no Registo de Viagens** - junta dados com prazos de retenção diferentes no mesmo componente.
